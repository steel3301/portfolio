# Portfolio Website — AI Agent Build Specification

## 1. Objective

Build a premium personal portfolio website for **Kaustubh Ravindra Warme**, an AI-focused Computer Science undergraduate specializing in:

* AI / LLM systems
* Agentic AI
* RAG
* Machine Learning / Deep Learning
* Computer Vision
* Federated Learning
* MLOps
* Cloud-native engineering
* Full-stack development

The website must feel like the portfolio of someone who **builds real AI systems**, not someone displaying a list of technologies.

Primary objective:

> Make a recruiter, researcher, engineering manager, or technical founder understand within 30–60 seconds what Kaustubh builds, how technically strong he is, and which projects demonstrate that ability.

Secondary objectives:

* Encourage visitors to inspect projects.
* Make technical depth obvious without creating visual clutter.
* Make the resume and contact information easily accessible.
* Make the site memorable through its visual identity.
* Communicate an engineering/research personality rather than a corporate template aesthetic.

---

# 2. Core Design Direction

## Visual Aesthetic

Use a refined **Neo-Brutalist** aesthetic.

The design should combine:

* Editorial typography
* Strong geometric structure
* Thick borders
* High contrast
* Large typography
* Hard rectangular cards
* Intentional asymmetry
* Slightly unconventional layouts
* Minimal shadows
* Minimal animation
* Almost no gradients
* No glassmorphism
* No excessive rounded cards
* No generic SaaS dashboard appearance

Think:

**engineering notebook + modern editorial design + experimental technology lab**

rather than:

**startup landing page + generic developer portfolio**

---

# 3. Design Philosophy

Every visual decision should communicate one of three ideas:

### A. Technical

The visitor should feel that the website belongs to an engineer.

Use:

* system diagrams
* architecture snippets
* metrics
* technical tags
* repositories
* deployment information
* concise technical explanations

### B. Experimental

The site should feel like the work is being actively explored and built.

Use:

* project status indicators
* "experiments"
* research notation
* system labels
* small technical metadata
* subtle interactive details

### C. Human

Avoid making the entire portfolio feel like documentation.

Include:

* a short personal introduction
* current interests
* research direction
* career goals
* a clear way to contact Kaustubh

The site should still feel personal.

---

# 4. Recommended Tech Stack

Prefer a modern React-based stack.

Recommended:

* Next.js
* TypeScript
* Tailwind CSS
* Framer Motion for restrained animations
* MDX or structured TypeScript data for projects
* Lucide icons or similarly minimal icon system
* Vercel or equivalent deployment

Do not introduce unnecessary dependencies.

Architecture should remain simple enough that the owner can easily modify:

* projects
* skills
* experience
* research
* links
* resume
* contact information

# 23. Typography

Typography is extremely important.

Use one strong display font and one neutral supporting font.

Suggested direction:

Display:

* Space Grotesk
* Geist
* IBM Plex Sans
* Archivo
* similar bold grotesque

Supporting:

* Inter
* IBM Plex Sans
* Geist

Optional monospace:

* IBM Plex Mono
* JetBrains Mono

Use monospace only for:

* metadata
* technology labels
* system status
* small technical annotations

Do not use monospace for the entire page.

---

# 24. Borders / Cards

Neo-Brutalist styling should use borders intentionally.

Example:

```css
border: 2px solid #111;
```

Cards should feel physical and flat.

Use:

* hard borders
* tiny corner radius or no radius
* occasional offset shadows

Example:

```css
box-shadow: 6px 6px 0 #111;
```

Do not apply this effect to every element.

Use it selectively for important interactive objects.

---

# 25. Grid

Use a strict underlying grid.

Desktop:

12-column layout.

Mobile:

4-column layout.

Use asymmetric spans.

Example:

```text
┌───────────────┬───────┐
│               │       │
│ PROJECT 01    │ META  │
│               │       │
├───────┬───────┴───────┤
│ STAT  │ ARCHITECTURE   │
└───────┴───────────────┘
```

The asymmetry should feel intentional.

Do not randomly position elements.

---

# 26. Animation Rules

Animation should be subtle and purposeful.

Allowed:

* section reveal
* border expansion
* project hover movement
* node activation
* text reveal
* smooth navigation
* tiny cursor interactions

Avoid:

* excessive parallax
* spinning 3D objects
* constant background animation
* particle backgrounds
* huge page-load animations
* scroll-jacking

Animation must never interfere with readability or accessibility.

---

# 27. Cursor Interaction

Desktop can have a small custom cursor enhancement.

Example:

Hovering over:

`VIEW SYSTEM →`

causes a small label:

`OPEN`

or a small accent indicator.

Do not replace the normal cursor entirely unless there is a strong accessibility fallback.

---

# 28. Mobile Design

Mobile is not a reduced desktop layout.

Redesign the layout for narrow screens.

Important:

* preserve large typography
* stack asymmetric sections
* maintain borders
* keep navigation simple
* avoid horizontal overflow
* make project architecture diagrams scrollable where required
* ensure all buttons have sufficient touch area

Hero should remain visually strong on mobile.

---

# 29. Accessibility

The agent must implement:

* semantic HTML
* proper heading hierarchy
* keyboard navigation
* visible focus states
* sufficient contrast
* alt text
* accessible buttons
* reduced motion support
* accessible external links

Support:

```css
prefers-reduced-motion
```

Animations should stop or simplify when required.

---

# 30. Performance

Performance is part of the portfolio's credibility.

Requirements:

* optimize images
* lazy-load noncritical media
* minimize JavaScript
* avoid huge animation libraries when unnecessary
* optimize fonts
* use Next.js image optimization
* avoid video backgrounds
* avoid unnecessary client components

Target:

* excellent Lighthouse performance
* fast first contentful paint
* minimal layout shift

---

# 46. Final Design Test

Before delivering the website, the AI agent should ask itself:

> "If the text were removed, would the visual system still feel like a technical portfolio?"

Then:

> "If the visual styling were removed, would the projects still demonstrate serious engineering ability?"

The answer to both should be yes.

The website's differentiation should come from the combination of:

**strong visual identity + technically credible work + unusually clear presentation.**

That is the target.
